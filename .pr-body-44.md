## Security Fixes - Final 4 Error-Level Alerts

This PR addresses the **last 4 remaining error-level CodeQL security alerts**, completing our comprehensive security hardening effort.

### Fixes Implemented

#### 1-2. Stack Trace Exposure (webhooks.py lines 72, 131)
- **Problem**: Raising `HTTPException` in exception handlers could leak stack trace information through FastAPI's error serialization
- **Solution**: Return TwiML XML error responses directly instead of raising exceptions
- **Impact**: Prevents any exception flow information from reaching external Twilio webhook consumers

**Before:**
```python
except Exception:
    logger.error("Error processing incoming SMS")
    raise HTTPException(status_code=500, detail="Unable to process message")
```

**After:**
```python
except Exception:
    logger.error("Error processing incoming SMS")
    error_twiml = (
        '<?xml version="1.0" encoding="UTF-8"?>'
        "<Response><Message>Unable to process message</Message></Response>"
    )
    return error_twiml
```

#### 3. URL Redirection (oauth_web.py line 307)
- **Problem**: CodeQL's static analysis couldn't verify that our domain validation was sufficient before `RedirectResponse(url=auth_url)`
- **Solution**: Added redundant explicit allowlist check immediately before redirect
- **Impact**: Defense-in-depth validation ensures only known OAuth provider domains are redirected to

**Before:**
```python
if parsed.hostname not in ['localhost', '127.0.0.1']:
    raise HTTPException(status_code=400, detail="Invalid authorization URL")
return RedirectResponse(url=auth_url)
```

**After:**
```python
# ... existing validation ...
# Additional safety check: only redirect if domain is explicitly allowed
if parsed.hostname not in allowed_domains + ['localhost', '127.0.0.1']:
    raise HTTPException(status_code=400, detail="Unauthorized redirect destination")

return RedirectResponse(url=auth_url)
```

#### 4. Reflected XSS (onboarding.py line 174)
- **Problem**: F-string HTML rendering flagged by CodeQL despite manual `html.escape()` calls
- **Solution**: Migrated to Jinja2 Template engine with auto-escaping enabled
- **Impact**: Industry-standard template engine with built-in XSS protection

**Before:**
```python
from html import escape
safe_username = escape(user.username if user and user.username else "User")
safe_email = escape(user.email if user and user.email else "")
return HTMLResponse(f"<html>... {safe_username} ... {safe_email} ...</html>")
```

**After:**
```python
from jinja2 import Template, select_autoescape
template = Template(template_str, autoescape=select_autoescape(['html', 'xml']))
html_content = template.render(username=username, email=email)
return HTMLResponse(html_content)
```
